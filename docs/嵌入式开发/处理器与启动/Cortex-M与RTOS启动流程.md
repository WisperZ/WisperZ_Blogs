# Cortex-M 与 RTOS 启动流程 {#_1}

在 **Cortex-M4** 板子的嵌入式操作系统中，启动流程一般涉及从复位（`reset`）开始，到操作系统的初始化，再到线程创建并进入调度过程。这个过程通常包括以下几个阶段：

## 1. **复位阶段（Reset Phase）**

当 **Cortex-M4** 处理器复位时，硬件会将程序计数器（PC）设置为启动地址，通常是 **复位向量（reset vector）**。复位时，处理器会加载位于内存中的 `reset_handler`（复位异常处理函数）。

- **硬件复位**：硬件复位后，Cortex-M4 的复位向量会指向 `reset_handler`。
- **Stack Pointer 初始化**：复位向量会将栈指针（SP）初始化为系统栈的初始地址。Cortex-M 系列处理器将栈指针（SP）存放在内存的顶部。
- **数据区和 BSS 区域初始化**：将 `.data` 段的初始化数据从存储器拷贝到 RAM 中，同时清空 `.bss` 段（未初始化的全局变量和静态变量）区域。

## 2. **启动文件初始化**

在 `reset_handler` 中，会做一些基本的初始化工作。常见的启动文件（如 `startup.s` 或 `startup.c`）会进行以下操作：

1. **初始化堆栈指针（SP）**：
    
    - Cortex-M4 会使用复位向量表中的栈指针（SP），并且此指针已经指向 RAM 区域的末端。此时，SP 会被设置为系统的初始栈指针地址。
2. **初始化数据段**：
    
    - 将 `.data` 段（全局变量的初始化值）从 ROM 中复制到 RAM 中。
3. **清空 BSS 段**：
    
    - 将 `.bss` 段（未初始化的全局变量）清零。
4. **设置中断向量表**：
    
    - 设置中断向量表地址到处理器的 `VTOR`（Vector Table Offset Register）寄存器。中断向量表包含所有异常（如 NMI、硬件中断、系统中断等）的处理函数地址。

## 3. **开启中断和异常**

在启动代码的后期，我们通常会开启系统的中断，特别是：

- **SysTick 定时器**：SysTick 是 Cortex-M4 上的系统定时器，用于生成定时中断，它通常被用来触发操作系统的任务调度。
- **启用中断**：`cpsie i` 指令会允许中断，并且开启全局中断使能位（`I` 位）。通常在这个阶段，我们需要开启 PendSV 和 SysTick 中断。

## 4. **调用系统初始化函数**

操作系统的初始化函数（例如 `os_init()` 或类似名称的函数）通常会在启动文件中的 `main()` 函数或者 `reset_handler` 中被调用。在这个函数中，操作系统会完成一些初始化操作：

1. **初始化内核资源**：
    - **内存管理**：初始化内存池、堆栈等资源管理系统。
    - **硬件抽象层（HAL）初始化**：初始化外设如串口、GPIO、时钟等。
2. **初始化调度器**：
    - **调度器初始化**：为多任务调度设置任务队列，初始化时间片、优先级等。此时系统会将内核初始化为多任务处理模式。
    - **启用系统定时器（SysTick）**：SysTick 定时器通常用于周期性地触发任务调度器，这个定时器通常会用于更新时间片。

## 5. **创建第一个线程（Task Creation）**

操作系统会创建一个或者多个任务（线程）。任务的创建通常是通过一个任务管理模块来实现，以下是常见的步骤：

1. **创建主线程**：
    
    - 调度器初始化后，操作系统会启动主线程。这个线程可能是应用程序中最先执行的线程。
    - **堆栈初始化**：为每个线程分配堆栈，并设置堆栈指针。
2. **创建其他任务（如果有）**：
    
    - 如果系统中有多个任务，操作系统会根据调度策略逐一创建任务。每个任务通常会分配一个堆栈、设置任务控制块（TCB），并将其添加到调度队列中。
3. **设置任务的优先级、调度策略等**：
    
    - 在任务创建时，还会设置任务的优先级、调度策略（如抢占式、时间片等）以及任务状态。

## 6. **启动调度器**

当所有任务都被创建后，操作系统会启动调度器，开始执行任务的调度。调度器负责选择当前哪个任务需要执行。此时，调度器通常会选择第一个线程或者主线程执行。

- **进入主循环**：操作系统会进入一个主循环，其中会定期检查是否需要切换任务，通常通过定时器（如 SysTick）来触发上下文切换。
- **上下文切换**：在任务调度过程中，操作系统会根据任务的优先级和时间片等调度策略，进行上下文切换。此时，**PendSV** 中断会被触发，处理器会将当前任务的上下文保存到堆栈，并加载下一个任务的上下文。

## 7. **任务调度与中断处理**

- **调度器选择任务**：操作系统通过设置定时器和触发中断来定期调用调度器，调度器根据任务优先级、任务状态等决定哪个任务应该被执行。
- **PendSV 中断**：当需要切换任务时，系统会通过 **PendSV** 中断触发上下文切换，保存当前任务的上下文（寄存器、堆栈等），然后恢复下一个任务的上下文。
- **中断服务**：当外设或系统事件发生时，硬件会触发中断，系统会根据中断优先级处理相应的中断服务程序。

## 8. **完成线程调度并开始运行**

一旦第一个线程（任务）开始执行，操作系统就开始实时地调度其他任务。调度器会根据任务的优先级、时间片等因素不断地切换任务，直到操作系统的生命周期结束。

## 典型的启动流程图

```plaintext
[Hardware Reset] 
       |
       v
[reset_handler] --> [Stack Pointer Setup]
       |
       v
[Initialize Data/BSS Segments] --> [Configure Interrupt Vector Table]
       |
       v
[Enable Global Interrupts (cpsie i)] --> [SysTick Init & PendSV Init]
       |
       v
[Call OS Init Functions] --> [Initialize Scheduler] --> [Create First Thread]
       |
       v
[Start Scheduler] --> [Enter Main Loop] --> [Task Scheduling and Context Switching]
```

## 总结

从 **复位阶段** 到 **线程创建完成**，操作系统经历了从硬件初始化、内存初始化、内核初始化、任务创建到启动调度器的整个过程。启动代码和系统初始化通常需要正确地配置中断、系统定时器、任务管理和调度机制，确保操作系统能够在实时应用中稳定运行。
