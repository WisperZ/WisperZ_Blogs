# ARM 多核启动 {#_1}

### **1. 什么是 Spin Table？**

**Spin Table** 是一种用于多核处理器启动的简单机制，主要用于 **非对称多处理（AMP）** 或 **对称多处理（SMP）** 的系统初始化。在多核环境中，CPU 启动通常需要明确主核和次核的启动过程，**Spin Table** 就是实现次核启动的一种常见方法。

#### **工作原理**

- **主核 (Primary Core)**：负责初始化整个系统，并为次核分配启动参数（例如程序入口地址）。
- **次核 (Secondary Core)**：
    1. 在系统复位后，所有次核通常会进入一个 "spin loop"（自旋循环）。
    2. 次核不断轮询特定的内存地址（称为 Spin Table）。
    3. 主核将次核的启动参数（如入口地址）写入 Spin Table。
    4. 次核检测到 Spin Table 的值已被设置，退出自旋循环，跳转到指定地址开始运行。

#### **优缺点**

- **优点**：
    - 实现简单，硬件和软件需求低。
    - 不需要复杂的启动协议支持，适用于早期 SoC 或简单嵌入式系统。
- **缺点**：
    - 缺乏标准化，依赖于特定的内存地址或硬件配置。
    - 不适合复杂的多核系统，效率较低。

### **2. 什么是 PSCI？**

**PSCI (Power State Coordination Interface)** 是 ARM 定义的一种标准化的接口，主要用于多核处理器的电源管理和 CPU 启动。在支持 **ARMv7-A** 和 **ARMv8-A** 的现代多核处理器中，PSCI 是广泛使用的启动机制。

#### **PSCI 的功能**

PSCI 提供了一组标准化的接口，用于管理多核系统的电源状态和处理器核心间的协作，包括：

1. **CPU 启动**：允许主核启动次核（与 Spin Table 类似，但更标准化）。
2. **CPU 关闭**：允许关闭未使用的 CPU 核心，以节省电源。
3. **系统重启**：通过 PSCI 接口重新启动整个系统。
4. **CPU 暂停/唤醒**：用于低功耗模式的核心控制。

#### **工作机制**

- PSCI 通常通过 **SMC (Secure Monitor Call)** 接口与固件（如 TF-A 或 U-Boot）进行交互。
- 主核通过调用 PSCI API（如 `PSCI_CPU_ON`），请求固件将次核从低功耗状态唤醒并启动。
- 次核根据启动参数（如入口地址）开始执行代码。

#### **优缺点**

- **优点**：
    - 标准化接口，适用于所有符合 ARM 规范的多核系统。
    - 提供了高级电源管理功能。
    - 与现代 ARM 固件（如 Trusted Firmware-A）集成良好。
- **缺点**：
    - 需要支持 PSCI 的固件，复杂性比 Spin Table 高。

---

### **3. Spin Table 和 PSCI 的对比**

|特性|Spin Table|PSCI|
|---|---|---|
|**适用场景**|简单嵌入式系统、AMP|现代多核系统、SMP|
|**启动机制**|次核自旋等待地址被设置|主核通过 API 请求固件启动次核|
|**标准化**|非标准化，依赖于具体实现|ARM 标准|
|**电源管理支持**|不支持|提供高级电源管理功能|
|**实现复杂度**|简单|较复杂，需要固件支持|

---

### **4. 实际应用场景**

- **Spin Table**：
    
    - 适用于早期 ARM 多核处理器或不需要复杂电源管理的嵌入式系统。
    - 在某些定制化的操作系统或裸机开发中仍可能使用。
- **PSCI**：
    
    - 现代 ARM 系统（如基于 Linux 或 OpenHarmony）的首选启动方式。
    - 广泛用于支持 DynamIQ 技术的多核处理器。

---

### **总结**

- 如果你的系统简单，只需要一个直接启动次核的方式，可以选择 **Spin Table**。
- 如果你使用的是现代 ARM 系统，尤其是需要复杂的电源管理功能，那么应该使用 **PSCI**。
